# English Paper PDF → Chinese Translation Prompt

一个面向 **ChatGPT 网页端** 的英文科技论文 PDF 中文翻译提示词。

目标不是做一个需要 API 的完整翻译工具，而是利用 ChatGPT 网页端现有模型能力：上传英文论文 PDF 与提示词文件，即可生成一份 **完整、可读、尽量保持原论文版式风格的中文 PDF**。

本项目重点解决的不是单纯逐句翻译，而是学术 PDF 翻译中更容易出问题的部分：双栏阅读顺序、跨栏/跨页段落续接、术语一致性、公式和参考文献保护、图表数据保持，以及英文转中文后重新排版造成的字号和空白问题。

## 特点

- **无需额外 API**：直接配合 ChatGPT 网页端使用。
- **完整翻译而非摘要**：要求正文、图注、表格文字、脚注、附录等按原文完整翻译。
- **自然段一一对应**：先恢复 PDF 中真实自然段，再进行翻译，不按视觉行逐行翻译。
- **支持双栏论文**：明确处理左栏、右栏、跨栏、跨页以及被图片/公式打断的段落。
- **术语一致性**：建立全文术语表，同一专业术语保持统一译法。
- **公式保护**：公式内容、编号和数学意义保持不变，避免 OCR 后错误重建。
- **参考文献冻结**：References/Bibliography 区域保持原文，不翻译、不重新编号。
- **图表数据保护**：图片内部默认保持原样；表格可翻译标题和表头，但数值、单位、变量和实验结果不得修改。
- **针对中文重新流排**：不在原英文文本框中机械替换文字，允许正文、图片、公式和表格按逻辑关系重新流动。
- **避免“小字体 + 大面积空白”**：以原论文正文主字号为基准，不允许为了保持原页数或固定坐标而优先缩小中文字号。
- **内部逐页 QA**：要求最终 PDF 渲染后逐页检查遗漏、断行、溢出、重叠、字号异常、公式清晰度等问题。

## 使用方法

### 1. 准备文件

将以下两个文件一起上传到 ChatGPT：

- 待翻译的英文论文 PDF
- [`SKILL.md`](./SKILL.md)

### 2. 发送指令

可以直接输入：

```text
按照 SKILL.md 的要求，完整翻译这篇论文并输出中文 PDF。
```

提示词本身已经包含完整执行要求，一般不需要再补充大量说明。

### 3. 输出

默认只要求生成：

```text
[论文名]_中文翻译.pdf
```

不会额外生成 Word、Markdown、TXT 或排版检查报告。

## 设计原则

本提示词将要求分为三个优先级。

### P0：不能牺牲

- 内容完整准确
- 原文与译文自然段一一对应
- 数学公式和编号正确
- 参考文献保持原样
- 图片、表格数据、数值、单位和引用编号不被修改
- 不使用明显过小字号换取表面版式一致

### P1：强要求

- 保持页面尺寸、单双栏结构和标题层级
- 保持图表、公式与对应正文的逻辑关系
- 中文正文可读、可选择、可复制、可检索
- 中文字体、标点和中英文混排符合设定规则

### P2：尽量满足

- 页数尽量接近原论文，但不强制一致
- 图表、公式和表格尽量位于原章节、原栏和相近视觉位置
- 保持原论文整体排版风格

核心原则是：

> 保持原论文的版式体系和逻辑关系，而不是机械保持每个对象的绝对坐标。

## 为什么不强制保持原页数

英文翻译成中文以后，文字长度和字体度量都会发生变化。

如果强制保持原页数和原对象坐标，模型往往只能通过缩小字号、压缩行距或留下大面积空白来完成排版，最终可读性反而更差。

本提示词允许：

- 中文正文自然重新流排；
- 图片、公式、表格作为完整对象进行合理纵向移动；
- 当前栏放不下时自然进入下一栏或下一页；
- 必要时增加页面。

但同时要求在不牺牲可读性的前提下避免无意义增加页数。

## 字号策略

中文正文不会简单机械复制英文正文的 point size，也不会为了塞回原文本框而主动缩小。

基本策略为：

1. 识别原论文正文主字号 `S_original`；
2. 中文正文默认从 `S_original` 开始排版；
3. 内容变长时优先重新流排，而不是缩小字体；
4. 只有局部排版确实困难时才允许小幅降低字号；
5. 普通 A4/Letter 双栏科技论文原则上不低于 `7.5 pt`；
6. 若页面仍有大量可用空间，不得继续缩小中文正文。

`7.5 pt` 是安全下限，不是推荐目标字号。

## 图片、公式和参考文献处理

### 图片

- 图片内容默认保持原样；
- 不翻译或覆盖图片内部英文；
- 不根据文字描述重新生成原图；
- 图注翻译为中文；
- 允许图片整体纵向移动，以配合中文正文重新流排。

### 公式

- 公式内容、编号和数学意义保持不变；
- 优先直接复用原 PDF 中的公式对象或公式区域；
- 禁止通过 OCR 识别结果重新输入复杂公式；
- 允许公式整体移动，但不得修改其内部内容和比例。

### 参考文献

从 `References` / `REFERENCES` / `BIBLIOGRAPHY` 开始到最后一条参考文献结束，默认完整保留原文：

- 不翻译；
- 不重新编号；
- 不修改 DOI、URL、作者、标题、期刊、年份和页码；
- 不改变参考文献区域自身的内部结构。

## 适用场景

适合：

- 计算机科学
- 人工智能 / 机器学习
- GPU / CUDA
- Computer Architecture
- PIM / Memory System
- FPGA / EDA
- 集成电路 / 微电子
- 光学、电子、通信等常见 STEM 论文
- IEEE、ACM、Elsevier、Springer 等常见单栏或双栏论文

对于以正文、公式、图表为主的正式科技论文效果最好。

## 已知限制

这个项目本质上是 **Prompt / Skill**，不是独立 PDF 翻译软件，因此最终效果仍依赖于当前 ChatGPT 模型和文件处理环境。

以下情况可能需要人工复核：

- 扫描版或图片型 PDF；
- 加密、损坏或无法正常提取文本的 PDF；
- 极复杂公式、特殊字体或非常规排版；
- 跨多栏、浮动对象极多的出版版 PDF；
- 表格结构极复杂、合并单元格很多的论文；
- 原 PDF 本身存在错误阅读顺序或文本层损坏。

另外，本提示词默认 **不翻译图片内部文字**。这是为了避免重绘图片造成信息失真。如果确实需要中文化图内标注，应单独处理图片。

## 推荐工作流

```text
English Paper PDF
    +
SKILL.md
    ↓
ChatGPT Web
    ↓
Chinese translated PDF
```

这条路线的重点是利用网页端模型已有能力，避免为了论文翻译额外维护 API、Token 计费、本地 OCR 和复杂翻译流水线。
